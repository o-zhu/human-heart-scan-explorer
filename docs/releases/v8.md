# Heart Explorer v8

## Opening and using the viewer

The application now loads its manifest and compact preview before requesting
optional cleanup metadata, Ultra collection inventory, chamber annotations or
ultrasound module data. The visible preview remains usable while the detailed
volume refines it. A failed initial load can be retried, and a newer source,
resolution or module choice supersedes a stale request.

Current slices, detailed volume preparation and arbitrary fine-plane sampling
receive foreground priority. Pointer, wheel, keyboard and captured-cursor input
suspend full-collection downloading. Nearby warming resumes after 180 ms of
quiet; whole-collection work resumes after 1.8 seconds, with one transfer at a
time and a 400 ms gap between files. Users can pause the collection independently
of these automatic yields. Data Saver, hidden-page, offline and storage limits
remain respected.

The complete orthogonal image collection is still prepared automatically during
idle time. Completion depends on how much idle time and storage are available;
selected files do not require the collection to finish. Encoded files remain in
persistent browser storage when available, while decoded RAM use stays bounded.
The original donor retains its existing cache names.

See [loading-priority-v8.md](../loading-priority-v8.md) for the executed scheduler
and actual app-boot checks. Those tests establish request ordering, cancellation,
cache isolation and race handling. They do not measure a user's browser frame
rate or network speed.

## A second independent donor

The source selector adds **UCL-ZCR-2629**, from Human Organ Atlas dataset
[2298522198](https://human-organ-atlas.esrf.fr/datasets/2298522198). The atlas labels
the age **under 18** and medical information **Disease free**. No exact age or sex
is supplied. The native source is 7.032 µm; the browser uses the following derived
representations:

| Representation | UCL-ZCR-2629 | Existing LADAF-2021-17 |
| --- | --- | --- |
| Fast preview | 225.024 µm; 1,741,458 encoded bytes | 635.2 µm; 1,931,449 encoded bytes |
| Detailed 3D volume | 112.512 µm; 10,494,022 encoded bytes | 317.6 µm; 13,152,058 encoded bytes |
| Ultra measured cut faces | 28.128 µm | 79.4 µm |
| Orthogonal image bank | 1,032 objects; 529,374,944 bytes | 1,097 objects; 507,669,076 bytes |
| Fine 3D block bank | 5,055 objects; 855,356,088 bytes | 5,127 objects; 805,012,353 bytes |

The approximately 1.385 GB new-donor bank is hosted data available on demand; it
is not an upfront page download. Full automatic preparation applies to the
orthogonal image bank. Fine 3D blocks are requested for the selected oblique
plane, with bounded memory and disk caches.

The new source went through source metadata and coordinate validation, display
windowing, conservative disconnected-debris cleanup, preview/detailed volume
encoding, cropped lossless orthogonal images, sparse fine bricks with interpolation
halos, source-specific annotation candidates and independent Echo/Flow/Probe
plane preparation. The specimens have separate manifests, assets, routes, caches
and physical scales. A donor switch opens a fresh viewer and cancels the outgoing
source's pending work.

The display conversion from source uint16 to a documented windowed uint8 interval
is explicit. Subsequent image/block compression is lossless relative to those
display values. It is not a claim that the browser delivers the full native
7.032 µm quantitative source.

## Evidence and limits

The independent [data verification](../donors/ucl-zcr-2629/data-verification.json)
checks all 6,087 hosted objects, source byte order, physical registration, volume
round trips, more than 55 million representative section pixels, and more than
21 million brick and halo values. The production GLSL also rendered the actual
new encoded volume and fine cut-face inputs in native offscreen EGL without GL
errors; its review and validation record are in the donor documentation.

The actual fine-volume backend additionally matched independent SciPy reformats
at all 8,301,494 tested pixels across adjusted oblique, empty exterior and prepared
planes. Cancellation, missing/corrupt data and bounded-concurrency checks passed.

Annotation labels are candidate regions, with uncertain tissue left neutral.
Source-derived new-donor Echo and inflow/outflow planes are exploratory starting
views, not clinically validated echocardiographic windows. Ultrasound comparison
movies are independent educational recordings, not recordings of either CT donor.
Physical scaling and data registration are tested; clinical identities require
expert review.

Portable exports include the complete four data banks, source, provenance,
preprocessing scripts and a dependency-free local Python server. The export's
`EXPORT-MANIFEST.json` records the exact source commit and every included file's
SHA-256. Deployment uploads are closed after the new immutable data banks have
been installed and checked.
