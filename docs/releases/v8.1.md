# Heart Explorer v8.1 — browser receiver correction

## Reported failure and cause

The v8 startup scheduler stored the native `setTimeout` and `clearTimeout`
functions on a `ScanActivity` instance, then invoked them as instance methods.
That supplied the instance as the native method's receiver. Safari rejects it
with **“Can only call Window.clearTimeout on instances of Window.”**

The failure occurred at `loadLevel → VolumeLoader.load → beginForeground →
publish`, before the preview worker or its download could begin. The existing
Node and injected-timer fixtures did not enforce a Window receiver, so the
earlier checks missed this compatibility regression.

## Correction

The default timer adapters now call `globalThis.setTimeout` and
`globalThis.clearTimeout` through wrappers. Their native receiver remains the
current Window or worker global, even when the adapters are called as instance
methods. Injected test clocks and the download priority policy are preserved.

The audit also found the same pattern in the Echo texture cache's default
`fetch` adapter. It now calls `globalThis.fetch` through a wrapper as well.

`tests/browser-receivers-v8_1.mjs` exercises the real scheduler and Echo cache
with strict receiver-checking host fixtures. It covers startup foreground work,
idle scheduling, gestures, disposal and a default texture fetch/decode. The
pre-fix source reproduces the reported exception; the corrected source passes.
Existing loading, actual app-boot and Echo cache tests are also rerun.

This is a focused JavaScript correction. Both donors' source data, textures,
annotations, cache names, compression and hosted data banks are unchanged.
An already open page must be reloaded to replace the old JavaScript; clicking
Try again inside that old page repeats the old code. Cached scan data does not
need to be cleared.

## Portable continuation

The corrected complete export is named `heart-explorer-v8.1-local.zip`, with a
matching `.sha256` companion. Use it instead of v8 when starting a fresh local
workspace. The local launch command remains `python3 scripts/serve-local.py`
(Windows: `py -3 scripts\serve-local.py`).
